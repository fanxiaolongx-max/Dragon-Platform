# NetCare RFC 方案与 AI 审计扩展

在 **F12 扩展打包 → 系统内置脚本 → NetCare RFC 方案与 AI 审计** 中选择脚本，按现有流程生成 Chrome / Edge Manifest V3 ZIP。

默认配置：MAIN 环境、点击启动、注入 iframe、带 Popup、关闭 License。打包器会拒绝不兼容的执行环境或 License 设置。扩展匹配以下三个 NetCare 主页面以及 KDP 的方案导出页面，不需要 Cookie 或所有网站权限：

- `https://netcare-ae.gts.huawei.com/p/netcare/index.html`
- `https://netcare.huawei.com/p/netcare/index.html`
- `https://netcare-de.gts.huawei.com/p/netcare/index.html`

## 安装和使用

1. 解压生成的 ZIP。
2. 打开 Chrome 的 `chrome://extensions`（Edge 使用 `edge://extensions`），启用开发者模式，选择“加载已解压的扩展程序”，选中包含 `manifest.json` 的目录。
3. 刷新以上任一已登录的 NetCare 页面。
4. 点击浏览器工具栏扩展图标，再点击“启动脚本”，右下角出现浮窗。输入一个或多个 RFC 单号（换行、空格、中英文逗号、分号或顿号分隔），点击“查找并下载”。无需 F12、手动切换上下文或第二次粘贴。
5. 多方案时选择方案并点击“确认方案”；浏览器会保存带 RFC 单号前缀的 DOCX。

首次创建常驻导出 iframe 时，Chrome 根据清单自动注入 worker。worker 从 `location.ancestorOrigins` 获取它实际所属主站的域名，校验白名单后只接受该父窗口的消息，回传消息也只指定该域名。不同主站的标签页不会共用消息连接。导出服务地址从原生下载入口动态读取，不按主站域名推测。导出服务校验值留在 KDP 自己的上下文中使用，不发送给顶层页面、不写日志、不持久化。每个单号均先经过网站原生方案下载入口，包括其授权检查。

## 在线方案画中画 Beta

在“工具设置 → 常规 → 测试功能”开启“在线方案画中画总览（Beta）”，保存后生效；默认关闭。在线方案继续以不抢焦点的后台页签打开。主页面按当前打开的方案显示独立卡片，配有流动渐变边框；点击图片或放大按钮可在本页放大，拖动标题移动，拖动右下角按 16:10 缩放。总览可排列、暂停、收起；缩窄浏览器会自动重新排列。

这是定期更新的只读图片预览。放大后用滚轮、上一屏、下一屏和回顶部浏览；点击“打开原页”可操作原网站。每轮最多更新两个可见预览，约每 3.5 秒检查页签列表，同一卡片更新间隔至少 8 秒；页面后台或总览收起时暂停自动截图。关闭在线页签后卡片自动移除，自动关闭审计页签同样适用。关闭 Beta 或关闭插件主浮窗会停止刷新并释放预览，但不会关闭原页签。

只预览当前主页面由插件打开、仍指向同一 RFC 的方案页签；关闭后重新打开主页面时不会接管其他主页面的方案。扩展更新前缺少来源记录的旧页签不会自动接管，需要重新通过插件打开。预览失败、原 iframe 不可访问或登录失效时显示提示，可使用原页查看。预览图片仅留在页面内存，不进入日志、快照或 AI 请求；移动、缩放、放大、翻页等操作可记录到既有插件日志，并带来源 RFC 和运行标识。

## 范围和限制

- 当前支持已观察到的新版 RFC 数字化方案页面；离线附件、归档单及以上三个域名之外的 NetCare 站点尚未验证，不会自动扩大域名权限。
- 在不同站点输入该站点自己的作业单号，不假定单号跨站相同；德国站使用 `NC20260924100081` 验证。
- 登录过期、网站权限提示、导出服务不可用或浏览器阻止下载时，按页面提示处理后重试。
- 每 5 秒查询转换状态，最多等待 10 分钟；不将登录页或普通错误响应保存为 DOCX。
- “停止”只停止客户端请求和等待，不撤销服务端任务；扩展 Popup 的“停止脚本”或浮窗“×”会停止客户端任务并清理浮窗及连接。再次点击“启动脚本”可重新显示；刷新页面后需重新启动。
- 前端内置工具源与运行时工具目录独立。更新仓库后，运行中的平台如仍展示旧脚本列表，需要通过现有“系统工具更新”流程应用 **F12 扩展打包** 的更新；不要手工覆盖用户工具目录。

## 批量与并发

- 每批最多 50 个 RFC，自动转大写、去重；存在无效单号时先提示，不启动整批。
- 默认同时运行 3 个导出任务，可选择 1–10。网站共用的查询/授权界面依次操作，各单 Word 转换和下载独立并行。
- 每单独立显示排队、授权、转换、已发起保存或错误。一单失败后继续处理剩余单号。
- “停止”停止当前批次等待、轮询及未开始的单号，不取消已经提交到服务端的转换任务。可修改输入后再执行。
- Chrome 可能按其网站下载设置拦截连续保存，请在下载记录中确认实际文件，必要时由用户允许该站点多文件下载。
- 多个站点分别在各自标签页输入其可访问的单号；本工具不会将某站失败单号自动提交到其他站点。

## 域名与启动方式

三个入口域名均在匹配网址和网站权限中。海外及德国入口使用 `de.kdp.gts.huawei.com` 等 `*.kdp.gts.huawei.com` 服务，中国区入口（`netcare.huawei.com`）使用 `kdp.idp.huawei.com` 服务；匹配 `https://*.kdp.gts.huawei.com/ows1/static/editor/IdpLiteView/PublishLiteView.html*` 与 `https://*.kdp.idp.huawei.com/ows1/static/editor/IdpLiteView/PublishLiteView.html*`（及对应 `OwsPage.html*`）同时覆盖两套 KDP 域名，连接仍使用每单原生授权入口返回的实际地址。

点击启动模式只对 KDP 导出页声明自动 content script，主站浮窗由 Popup 的“启动脚本”注入。这让之后新建的跨域导出 iframe 自动初始化，用户无需再次粘贴。不要将 Chrome 的“网站访问权限”设为仅点击时：导出 iframe 需要扩展已有的 KDP 网站权限。可以使用“在特定网站上”，确认主站和 KDP 域名都获准访问。

## 下载时同时在线打开

浮窗新增默认勾选的“同时在线打开方案”。每单先走原生下载授权，再点击所选方案名称，取得该单原生 `OwsPage.html` 地址，保留其只读/评审等原生参数，随后返回 RFC 信息页面。扩展通过隔离环境 relay 和后台 `chrome.tabs.create` 在后台新建独立页签，不依赖网页弹窗的临时用户手势。

- 取消勾选时只下载 Word。
- 多方案时只打开本次选择并下载的方案；不会自动打开所有其他方案。
- 每单展示在线方案链接及打开结果；在线打开失败不阻断 Word 下载，可点击链接重试。
- 停止不会关闭已经打开的在线方案页签，也不会取消服务端 Word 转换。
- 后台只接受三个主站顶层页面的请求，校验 HTTPS KDP 主机、固定 `OwsPage.html` 路径及两个单号参数一致；不新增 Cookie 或所有网站权限。
- 在线页面可能包含网站原生评审操作，当前扩展只打开页面，不填写或提交内容。后续检查规则尚未实现。

### 在已打开页面启动 / 更新扩展后重连

Popup“启动脚本”会先在当前主站顶层页面的 ISOLATED 环境注入开页 relay，再启动 MAIN 环境的浮窗。即使 NetCare 页面在扩展安装前已打开，或主站的自动注入被 Chrome 网站访问设置暂缓，也能通过点击启动初始化开页连接。重新点击启动会移除旧 relay 监听器，避免更新扩展后复用失效的连接。

原页面短暂打开方案再返回，是为了取得原生在线地址；新页签由后台创建，主页面返回 RFC 后新页签仍保留。KDP 下载 worker 仍需要原有网站权限。

## 在线方案附件与章节 ZIP

在线方案 `OwsPage.html` 新页签自动显示“方案附件与章节”浮窗，并自动扫描完整原生目录，包含当前没有在页面渲染的章节。通过网站 `GetTopicSync` 读取正文，通过原生附件链接标记识别 TXT、Word、ZIP、RAR、MSG 等所有文件类型，不把普通网页链接或拓扑图片当作附件。

1. 确认扫描结束，浮窗会列出每个附件的章节号与原名称。
2. 展开“选择提取章节”，勾选需要的章节，或选择全部。
3. 等待 Word 下载结束，方案文件名将通过扩展本地连接自动填入；也可以填写已有 Word 文件名。
4. 点击“下载 ZIP”，全部识别到的附件和已选章节 TXT 一起打包。

ZIP 基础文件名与 Word 一致，只将 `.docx` 改为 `.zip`。包内附件如 `3.2-FW Checklist CLI V1.txt`；章节文本如 `1.1-Change Purpose.txt`。相同章节下重名文件自动添加 `(2)` 等后缀；同一附件在不同章节引用时分别保留，便于核对章节。TXT 使用 UTF-8 BOM，表格用制表符分隔。

包内 `清单.txt` 包含附件/章节对应关系和逐项错误。某个文件下载失败不会伪装成成功；扫描有错误会明确提示清单不完整。扫描/下载停止后不会自动生成 ZIP。当前单文件打包上限 100MB、整包 500MB，ZIP 采用标准 Store 模式（不压缩内容）。

扩展仅在本地保存每个 RFC 的 Word 文件名，用于 ZIP 对齐命名；不保存方案正文、附件内容或凭证。新增网站权限限于原 KDP 域下 `OwsPage.html`。更新扩展后刷新已经打开的在线页签，或在该页签点击扩展的“启动脚本”。


## 默认提取设置（v1.0.7）

在启动浮窗点击“设置”，在“常规”和“章节规则”中编辑，附件和文本自动提取可分别开启。内置 NC20260903002788 的 34 个章节模板，预选 3.2 的附件和 1.1、3.2 的文本；两个自动开关默认关闭。每行支持修改序号、名称、附件/文本选项、删除，也可新增或恢复内置模板。修改后点击保存，设置保存在当前扩展的本地存储，三个 NetCare 入口共享；已经打开并开始扫描的方案应刷新或重新打开。

章节按序号和层级匹配，例如选 3.5 包含 3.5.3，但不会包含 3.50。父章节的附件/文本选择会锁定全部子章节；父提示词会在子章节引用并置灰锁定。取消父选择或清空父提示词后，子章节恢复自己的设置。导出名称采用实际方案的章节标题。

章节规则中的“序号缺失或名称不符时按章节名称纠错”默认关闭。开启后，同时核对编号与完整名称：编号未找到或对应名称与模板不同，按完整章节名称查找（忽略大小写、空格和标点），结合层级和父章节定位唯一候选；找到的章节及其子章节继续按原规则下载与审计，并保留实际序号、标题和纠错记录。无法唯一定位时提示核查，不将错误编号处的内容提交审计。

自动提取中的“审计完成后自动关闭在线方案页签”默认关闭。开启后，在审计完成、汇总与快照保存成功、ZIP 已发起下载后关闭本扩展打开的在线页签；出错、停止或审计证据缺失时保留页签。只下载而不审计时不关闭。审计模型必须返回中英双语简短结论与问题列表（最多5项），结果页面和 Excel 按插件当前语言只显示对应的中文或英文；原始章节名称、文件名、用户规则、方案证据和技术错误原文保留。启用自动提取后，主浮窗会开启在线打开；在线页只读取选定章节，等待本次 Word 文件名后自动生成 ZIP。未找到章节或下载失败会在页面/清单中说明。在线页的“扫描全部章节”可重新做完整扫描，“下载 ZIP”仍可手动打包所有已扫描附件与勾选文本。

在线页面先加载附件链接，不能认为附件文件已经全部下载。首次提取附件仍会请求服务器，浏览器 HTTP 缓存是否生效取决于站点响应。同一在线页成功下载的附件保留在内存，重复引用/再次打包不重复下载；刷新或关闭页面后内存缓存消失。不会解开嵌套 ZIP/RAR。

采集请求默认间隔 1.5 秒，可设 1–30 秒。扩展后台为多个在线页共享一个请求启动队列，用于章节读取、原生附件状态检查和附件下载；这不改变原有 Word 导出并发，也不替代服务器限流规则。无远程限流豁免保证。设置、文件名保存在扩展本地，附件与正文只在页面内存中处理。


## 设置界面与配置备份（v1.0.8）

主浮窗只保留 RFC 输入、当前偏好摘要、下载操作和进度，右上角设置按钮打开居中大弹窗。常规页管理并发数、在线打开、请求间隔、自动提取与配置导入导出；章节规则页以表格编辑序号、名称、附件/文本选项，支持增删。

所有上述设置点击保存后写入 chrome.storage.local，浏览器重启后保留，同一扩展的三个入口共享。旧版设置自动补充默认并发3、在线打开true。存储保留到用户清除扩展数据或卸载；不是跨设备云同步。

导出当前编辑草稿为 netcare-rfc-settings.json，包含format与version。导入支持当前版本格式，限制2MB并校验章节序号/重复项/启用规则；导入和恢复默认只修改草稿，保存后才覆盖现有配置。取消或Esc放弃未保存修改。配置不包含登录信息、附件、方案正文或RFC下载记录。


## AI 审计（v1.0.12）

工具设置新增“AI 对接”，支持与题库助手一致的 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini GenerateContent 协议，以及兼容这些协议的服务。可新增/删除/编辑多个模型，填写API基地址或完整接口地址、模型ID和Key，连接测试只发送固定测试文本。点击“保存并用于审计”选择审计模型。模型编辑页来自扩展自身，通过 iframe 展示，也可点击新页签打开；Key仅保存于扩展本地，不经过网站页面消息或站点localStorage，普通配置JSON不含模型Key。

在“常规”开启“AI审计”，并在“章节规则”分别填写附件/文本检查提示词（每条4000字符）。有提示词的对应提取勾选项自动选中并禁用；清空提示词后恢复可编辑。总开关默认关闭；关闭时不调用模型，提示词保留。开启审计自动启用所需章节提取与在线打开。

下载采集阶段保留章节文本、TXT附件文本和元数据，并在在线方案页 localStorage 的 tpNetcareAuditCacheV1 暂存，最多5个RFC、总计2MB、24小时有效；下次进入采集页或写入时清理过期记录。识别到的密码、Token、Cookie、Authorization、API Key和私钥值在暂存与模型请求中脱敏，原下载文件不改写。暂存失败不会自动提交模型，报告说明需人工复核。

当前审计范围是章节文本、UTF-8/UTF-16LE TXT附件，不会自动打开Word/PDF/ZIP/RAR/MSG或解包。非TXT、缺失附件/章节、超60000字符、编码失败、HTTP/超时/模型JSON异常均为needs_review，不会作为通过。单RFC按条目顺序审计，多RFC由后台限制最多8个活动模型请求，60秒超时，停止会取消当前模型请求。

审计依据来自各章节单独提示词，章节/附件内容按不可信证据处理。 新审计采用明确的三态判定：全部适用审计要求有证据满足时为 pass；已成功提取的内容中有任一要求明确不满足（包括必需内容缺失）时为 fail；没有确认违规，但因源材料无法读取、确实缺失或规则含糊而无法判断时为 needs_review。确认违规优先于其他审计点的不确定性。仅当用户规则要求具体 KPI、测试用例时，缺少这些内容才是不通过，工具不额外添加审计要求。读取、解析或模型调用异常仍标记需人工核查。历史报告不自动改判，需重新审计以使用新判定规则。每次ZIP增加AI审计结果.json、AI审计结果.txt，按条目显示pass/fail/needs_review、摘要、发现和模型ID，结果同时更新到localStorage暂存。原方案Word与ZIP命名方式保留。审计报告供人工复核，不直接提交网站审批。

为支持自定义模型地址，AI联网权限与题库助手一致：HTTPS服务和localhost/127.0.0.1的HTTP服务。站点脚本注入范围仍为既有NetCare/OWS路径，模型请求从扩展后台发出，不携带网站Cookie。

Anthropic 新模型可选择 ANTHROPIC_AUTH_TOKEN（Bearer）或 ANTHROPIC_API_KEY（x-api-key）；旧配置未记录认证模式时保留 x-api-key 行为。连接测试直接使用当前填写的配置，无需先保存，显示 HTTP 状态、耗时、接口、协议、模型及脱敏后的返回正文；请求失败也展示可用的详细返回。

“自动提取”与“同时在线打开方案”是独立开关：两者都关闭且 AI 审计关闭时仅下载 Word；仅在线打开开启时会打开方案，但不自动提取。“自动提取”开启后会打开在线方案并提取所选章节；AI 审计开启时也会自动提取有审计提示词的必需内容。

主浮窗增加“审计结果”入口，收到在线方案的审计结果后自动弹出汇总（设置窗打开时可稍后手动查看）。按 RFC 和章节显示审计点、通过/不通过/需人工复核、理由、发现、章节文本与 TXT 附件内容。显示证据与报告脱敏后存于扩展本地，最多5个RFC、总计2MB、24小时有效；该汇总不包含模型Key。

非 Anthropic 协议下认证选择器置灰，其值不会参与请求。连接测试使用当前草稿，审计使用已保存模型；测试成功后如有修改应点击“保存并用于审计”。AI 审计失败的原因可展开查看 HTTP 状态、耗时、实际接口、模型、认证字段名称、是否配置Key及脱敏后的服务器返回。不会显示认证值或请求正文；详细错误同时保留于结果 JSON。旧版只保存 HTTP 状态的历史报告无法还原返回正文，需重试获取。

## 完整备份与截图（v1.0.12）

截图定位不到、超过2400万像素/高30000像素/宽6000像素、PNG编码错误等会列入清单。DOM截图对复杂CSS、跨域图像或字体存在浏览器渲染限制，不替代原始方案；不会下载附件内部Word/PDF内容作为截图。截图只留于本地ZIP，当前不提交AI，也不写入配置备份。

## 章节树、整章审计与统一 ZIP

章节规则采用树状连线和输入框整体缩进区分层级，深浅主题均可识别。父章节的选择与提示词锁定其子章节，子章节草稿保持独立保存。审计按所选父章节汇总全部后代证据，同一章节的文本与附件分别形成审计项；结果表和 Excel 将两类审计项合并到一个父章节单元格，具体问题仍引用真实子章节编号与文件名。汇总证据为空、缺失或超过当前 60000 字符请求上限时明确标记需人工核查，不截断后给出通过结论。已有历史结果保留原审计记录，新审计采用整章汇总。

开启自动提取时，一个 RFC 下载一个 ZIP，方案 Word 位于根目录，附件、单独提取的文本和 PNG 位于对应章节文件夹；选择父章节时，所有子章节材料归入所选父章节文件夹，并保留实际子章节编号的文件名。仅下载 Word 时仍单独保存 DOCX。Word 缓存失败会单独保存 Word 并提示，在线页不将缺少 Word 的 ZIP 当作完整打包。审计材料导出和快照保留原始文件与相同章节目录，包括 PNG。

结果按钮、汇总标题和快照选择框分别显示方案数与审计项数；历史快照列表数不代表当前结果包含的方案数。开始新批次时清空当前视图，并只接受本次 RFC 的新审计记录，避免旧批次或同一 RFC 的旧记录混入；保存当前快照也使用该范围。选择历史快照后，表格只展示所选快照内容。


## 新增章节定位与截图性能提示

“添加章节”先选择新增顶级章节或指定父章节；若刚编辑过某行，默认建议在该行下面添加子章节。序号根据现有同层级（包括已存在的更深后代）自动生成下一项，按数字层级插入，滚动到新行并聚焦章节名称。序号、名称与规则仍可编辑，修改后保存生效；取消或 Escape 仅收起新增面板，不添加空行。

审计表头吸附在滚动区域最上方，以不透明的整行表头覆盖滚动内容，避免顶部留白漏出下方单元格。

`Canvas2D: Multiple readback operations…willReadFrequently` 是浏览器性能提示，表示频繁读取 Canvas 像素；它本身不是审计、下载或截图异常。扩展内的截图组件将 Canvas 复制到支持读取优化的临时画布上进行检查，避免反复读取原页面 Canvas；保留跨域污染检查，不修改网站的 Canvas 上下文。

## 章节匹配范围与自动关闭诊断

文本和附件分别以所选最外层父章节为匹配范围。父章节按编号与当前纠错开关定位后，仅提取实际目录中该章节及其后代；继承选中的子章节不再独立全局按名称兜底，避免将目录外同名章节混入父章节文件夹。父章节整体未找到时，仍可按完整名称兜底，并提取兜底命中的实际子树；独立选择子章节时也保留兜底能力。纠错开关关闭时按序号匹配；开启时名称不符也触发纠错。清单记录配置章节与实际章节映射，审计结果章节列以配置为标题，并显示原章节到实际章节的箭头与颜色区分。纠错记录随审计 JSON、历史快照、材料 ZIP 和 Excel 一起保存，旧结果不补写。

自动关闭不受通过、不通过或普通需人工核查结论影响；缺失审计材料、模型调用异常、提取/缓存错误、汇总或快照保存未确认、停止任务时仍保留页签。保留时在线浮窗明确显示暂停原因；扩展拒绝关闭或连接失败也会回显原因。仅关闭本扩展本次打开且仍停留在原方案 URL 的页签。

## 章节规则单一滚动与附件格式

章节规则页只让表格内部滚动，表格自适应设置窗剩余高度，导航和保存按钮始终在可见范围。表头吸附在内部滚动区域顶部。新增章节面板也位于该区域，新增后按编号插入并定位，不引入外层滚动。

下载附件不按 TXT 格式过滤：选中的章节及其后代中，原生附件链接指向的 PDF、Word、Excel、图片、ZIP、MSG 等均保存原始字节并加入最终 ZIP，单文件最多 100MB。仍需原生访问权限及有效下载响应；下载失败或超过限制会写入清单。AI 自动审计目前仅解析 UTF-8/UTF-16LE TXT，其它格式保留在 ZIP 并标记需人工核查，不会因无法解析而丢弃文件。

### 审计语言与截图展示

模型仍返回独立的中文和英文摘要及问题字段，方便切换语言；页面及单独导出的 Excel、材料 ZIP 与快照备份中的 Excel，均按导出时选择的语言显示表头、结论、原因和纠错标签。旧版“中文 / English”结果兼容拆分；没有对应译文的历史单语结果会提示重新审计，不凭空翻译。章节名称、文件名、用户填写的检查规则、原始证据和诊断返回保持原文。

开启“保存原始区域截图（PNG）”后，审计点内容列显示对应章节或附件位置的缩略图；按实际子章节及附件文件名关联，父章节审计会包含全部被审计子章节截图。点击图片在同页弹窗放大，点击大图可切换原图尺寸，Escape 只关闭图片预览。缩略图按可见区域读取，关闭或切换结果时释放图片地址；历史快照始终读取该快照绑定的图片。普通 PNG 附件不会被当成位置截图。

Excel 内嵌 PNG 原图，按比例缩放到审计点内容列的独立图片行；方案和父章节继续合并，结论与原因跨对应图片行合并。图片和文字分别留出空间，不覆盖审计内容。超过单元格上限的文字有明确提示。截图开关关闭、旧记录未缓存图片或缓存已过期时不补造图片，页面和 Excel 提示重新提取；材料 ZIP 同样包含带图 Excel。

工具设置新增“性能监控”。插件浮窗运行期间每 5 秒采集一次当前页面 JS 堆、长任务阻塞占比及前台定时器延迟；包含该页面的网站脚本，不是插件独占内存。稳定版 Chrome 不提供扩展独立 CPU 利用率，界面明确显示不可获取，并以主线程阻塞占比作为页面压力参考，不将它标为 CPU。浏览器不支持相关 API 时显示缺省值；后台页签的定时器节流不计入前台延迟。

当前主页面及其跨区域目标页、扩展打开的在线方案页按来源关联展示。趋势保存每分钟峰值，支持最近 24 小时、6 小时、1 小时、15 分钟，以及主页面/关联页面最大 JS 堆切换；不同页签可能共享堆，因此不求和。只显示实际采样，未运行插件、关闭页面、浏览器休眠或采样中断的时段留空，不补造连续历史。高阻塞、前台延迟、接近 JS 堆上限或超过两分钟无前台心跳时提示检查页面压力。来源列表同时显示后台、已关闭、浏览器休眠和采样暂停状态。页面本身已完全阻塞时，该页面不能即时刷新；可以由仍可响应的发起页面观察关联目标页的心跳。

指标使用扩展现有 IndexedDB 的独立 performance 表，旧版材料、配置、快照和日志升级时保留。仅保留 24 小时及最多 10000 条指标记录，写入时按分钟清理；关闭浏览器期间不会后台采样。指标不含网站正文、登录信息或密钥，不随快照日志/材料备份导出，也不计入审计材料容量统计。

中国、埃及、德国原生入口搜索引发的跨区域新页签，扩展会先关联发起页面、RFC 和批次，再验证目标网站及单号。目标页自动加载同一浮窗、沿用扩展保存的设置、继续原生查询/授权/导出及后续提取审计，进度和结果汇回发起页面，审计结果仍属于原批次。多次区域跳转保留原始来源，不重复开始全局批次。目标页本身的画中画总览不重复启动，目标页打开的在线方案可以由发起页统一查看。

仅接续三个已支持站点的 `/p/netcare/index.html` 与 `/rfc/network_tuning/` 页面；单号从原生 URL、同源详情 iframe 或输入框确认。目标新标签通过 opener 或 webNavigation 原生导航来源关联，不扫描或接管用户其它页签。页面内容延后加载时会在查询等待期内重试；其它单号、非支持站点、单号信息冲突、重复跳转循环均不会继续操作。停止会传给正在处理的目标页；关闭目标页会在来源页报告失败。原生网站登录、站点权限及下载授权仍需有效；网站把目标页改为其它路径或路由形式时需要提供实际 URL 验证，不能通过此功能绕过登录。

打包基线更新为 1.0.17；新增 `webNavigation` 权限用于关联不带 opener 的原生新标签。需要重新打包并更新扩展、刷新入口及在线方案页才能使用。相关功能在本地模拟网页和生成扩展背景脚本中验证；真实三地区网站及具体 RFC 的访问权限未在本次测试中验证。

## HTTP 模型、截图恢复与同步控制（v1.0.18）

- NetCare 模型配置支持用户指定的 `http://` 与 `https://` 地址，包括公司内网服务器和自定义端口。连接测试与正式审计共用请求构建和传输逻辑；仍拒绝 URL 中的账号密码、查询参数、片段和其他协议，不附带浏览器 Cookie，也不自动跟随重定向。扩展增加 `http://*/*` 主机权限，需重新打包并更新扩展。模型协议与认证模式仍需和实际服务一致，根地址自动补齐对应的 `/v1/messages`、`/v1/chat/completions` 等路径。
- 截图每次重新检查章节序号与名称、定位当前 DOM。原始区域最多尝试三次，间隔 400ms、1000ms；有唯一原生目录入口时尝试点击加载。附件只在匹配章节内定位，拒绝歧义。
- 原始区域始终不可用时，使用扫描已读取的原生章节 XML 重建截图。重建内容会移除脚本、活动链接、表单等，并在图片和文件名明确标注“内容重建截图（非页面原图）”。它能保留章节内容证据，但不能证明原页面布局、动态控件或加载状态。停止任务后不再重试或重建。
- 原图和画中画预览共用每个方案的渲染队列，避免克隆和滚动相互干扰；画布与新增 html2canvas 克隆容器在成功、失败后释放。恢复记录和失败记录可在采集浮窗点击，查看各次错误码、错误信息、堆栈、已渲染章节数、区域尺寸及连接状态。记录写入插件日志、快照记录和 ZIP 的 `截图诊断.json`；“重新提取”生成新的 ZIP，不改写旧快照。
- Beta 总览默认关闭。开启后，每个方案横向占一列：上方固定比例的原页预览，下方更高的采集面板，支持扫描、下载、停止、文件名、章节勾选、折叠内容和截图诊断。可见面板约每两秒同步，原页预览约八秒更新；同类轮询每轮最多两个，离屏面板延后更新，展开查看的方案优先。隐藏进度后自动改为预览多行平铺。
- 总览仅传递扩展自身采集浮窗的受限结构与文本，不传递网站 HTML、事件脚本或任意 URL。控件带采集实例标识，关闭、刷新或禁用的控件无法继续执行；背景脚本验证主页面、方案归属、RFC 及目标页当前地址。审计原文、模型输出和状态保留源浮窗内容；日志与镜像文本进行已有敏感字段脱敏。
- 放大的画中画按图片比例与可用视口自动适配；可拖动右下角手动调整，点击“适应内容”恢复自动适配。预览图片仍为只读；网站原生编辑和业务操作使用“打开原页”。

验证：本地模拟方案覆盖了原图、未渲染章节的重建、同步控件与诊断查看；未连接用户公司 HTTP 服务，未验证具体 RFC 在真实 NetCare 网站的渲染状况。
