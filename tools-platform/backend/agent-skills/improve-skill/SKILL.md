# 完善技能 / Improve a Skill

目标：和用户一起根据实战经验、查询优化或业务补充，完善一个已有的 Skill，由用户确认后更新保存（系统在保存前会自动备份，支持随时回退）。

## 流程

1. 确认目标技能：
   - 优先通过对话中已加载的 Skill（如 `@netcare-data`）或用户明确提及的技能标识识别；
   - 若未指明目标技能，询问用户要完善哪个已有的 Skill（可列举当前对话中涉及的技能）。

2. 梳理问题与优化点（结合对话中的实际调用和排查经历）：
   - **痛点分析**：找表耗时长、单轮步数超限、基座接口超时（如超过 15s）、字段类型不明确、跨表关联报错等；
   - **前置追问**：识别哪些是查询前必须澄清的关键信息（如时间范围、组织代表处/BG、指标维度、统计粒度），在流程开头增加主动追问环节，避免盲目搜索；
   - **已知知识沉淀**：把本次验证成功的表名（如汇总表 DWS、明细表 DWD）、公共字典表（如 `common_data_rep`）及其关联键（如 `repoffice_code = dept_code`）、核心字段名沉淀为速查表，避免重复探查；
   - **策略优化**：优先使用 DWS 汇总表聚合、拆分复杂 SQL 避免超时、先小样本（LIMIT）验证再全量、排除占位空值等；
   - **边界清晰**：严格区分通用流程（适用于该类所有场景）与专属知识（仅适用于特定业务主题，如整改、风险等），严禁把局部经验误当成通用规则。

3. 规范起草：
   - 保留目标 Skill 原有的核心有效流程与约束，在其基础上做增量完善；
   - 控制长度，避免冗长代码块堆砌，结构清晰（前置澄清 → 查询策略 → 核心流程 → 主题专属速查）；
   - 不得把密码、Token、API Key 或真实机密写入 Skill。

4. 输出格式：
   - 最终草稿必须放在语言标记为 `skill` 的代码块中（三个反引号后紧跟 `skill`）；
   - front-matter 必须保持目标技能的 `id`（小写英文连字符），以便系统识别为对该技能的完善更新；
   - 代码块外简要说明本次主要完善的内容（如新增前置追问、沉淀整改已知表、增加防超时策略等），并提醒用户点击卡片上的「完善技能」按钮完成更新。系统会自动备份修改前版本，可在技能管理中随时查看历史或一键回退。
