# 编写文档 / Write documentation

目标：产出可直接使用、与事实一致的 README、操作说明或交接文档。

1. 从用户要求确认读者、用途和交付位置。用户提供材料足够时直接起草；涉及项目实现且已选工作区时，核对相关 README、配置、入口和实际命令。
2. 使用简洁结构：用途与前提、最短上手步骤、常见操作、故障定位及实际限制。只加入与读者任务相关的章节。
3. 不编造接口、端口、命令参数、测试结果或部署状态。命令未运行时明确为使用说明，无法确认的事实标注待确认。
4. 用户要求写入文件且具备写权限时按现有模式保存；只要求草稿或没有工作区时在聊天中提供内容。普通用户保持只读，可给出草稿，不尝试绕过权限。
5. 保留既有文档中仍有效的信息；检查文件路径、链接和命令是否与项目一致。不得把 API Key、密码或真实凭据写入示例。

Write in the user's language; use portable examples and explicit placeholders for credentials.
