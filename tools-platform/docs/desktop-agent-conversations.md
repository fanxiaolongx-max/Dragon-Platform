# 桌面 Agent 会话接入

## 使用

管理员打开「全局设置 → 桌面 Agent」，启用「本机桌面对话连接」并保存。首页对话侧栏的「桌面 Agent」分类提供服务商切换、搜索和「刷新列表」；开启自动刷新列表后默认每 20 秒更新最近列表。手动刷新会立即重新读取列表，跳过缓存和间隔等待，关闭自动刷新后仍可使用。进入该分类及切换厂商时自动打开该厂商第一个最近活跃对话；三枚图标按钮可直接切换，悬停显示名称，选中项用边框与底色区分。也可手动选择其他会话，并在支持发送时直接回复。每家默认最多显示 60 个最近会话，每个会话最多返回最近 200 条文本消息。

这里连接的是**运行平台后端的电脑**，不是访问网页的手机或另一台电脑。Electron 不是必需的：本机后端和桌面 Agent 运行时，普通 Web 页面也可以访问这项功能。首次绑定需要管理员明确启用，默认不向平台导入私人桌面历史。

| 客户端 | 最近会话与历史 | Web 发送 | 当前通道 |
| --- | --- | --- | --- |
| Codex 桌面 | 支持本地已保存文本记录 | 支持，原会话空闲时 | 原生桌面 Unix IPC，会话 UUID 不变 |
| Claude Code 桌面 | 支持本地 Code 会话记录 | 默认只读；可开启「模拟操作发送」（macOS） | 元数据与 transcript；发送走辅助功能模拟操作 |
| Antigravity 桌面 | 支持当前桌面侧栏可见会话与时间线 | 支持，原会话空闲且输入框没有草稿时 | 运行中桌面应用的本机 Chromium CDP |

Codex 需要本机桌面 IPC 可连接。Antigravity 需要运行中的桌面应用提供 `DevToolsActivePort`，打开网页历史会同步切换其桌面会话；当前连接器面向 Antigravity 桌面应用，不将另一款 Antigravity IDE 的 CLI 当成桌面连接。客户端升级造成协议或页面变化时，发送会明确失败。

Claude 的深链可以打开右侧讨论串，但不能由“成功打开窗口”推断消息会发到指定会话，因此不使用深链发送。模拟操作发送改为核对窗口标题与唯一输入框后再发送，并以 transcript 回执确认（见下文）；该路径默认关闭。

## 设置与隔离

- 设置包括启停、三家客户端开关、自动刷新列表、列表刷新间隔、列表数量、允许 Web 发送，以及 Claude 的「模拟操作发送」（默认关闭）。列表仅在该分类可见且网页位于前台时定时更新；关闭自动刷新时禁用间隔输入。打开的正文每 2.5 秒（忙碌/待确认）或 5 秒（空闲）独立刷新，不受列表刷新开关和间隔影响。设置页按可用宽度排列连接/列表参数和三家客户端卡片，连接状态直接展示在卡片内；窄屏纵向排列，详细说明折叠。
- 一个服务主机只绑定一个平台账号及租户；其他管理员或租户不能读取或抢占桌面历史。解绑后才可以重新绑定。
- 设置与发送回执使用 SQLite。主机绑定属于平台控制面；租户库保存该租户的设置和请求状态，不复制整份原始 transcript。
- 原生文件路径、目录、认证配置、工具调用输出和推理内容不进入返回的会话数据。正文及标题经过凭据脱敏；含凭据的发送请求被拒绝。
- 列表刷新和历史查看不触发模型任务。发送明确标出服务商及原会话，平台模型或 CLI 不会自动代答。

### Claude 模拟操作发送

Claude 桌面没有可确认目标会话的本地接口，发送因此像用户一样通过 macOS 辅助功能操作窗口，在「全局设置 → 桌面 Agent → Claude Code」单独开启，默认关闭：

1. 在左侧栏按会话标题找到唯一一行（子会话形如「标题 由 Claude 从 … 发起」）。找不到、重名或本机有同名 Claude 会话时拒绝，不猜测。Claude 侧栏不响应辅助功能的合成“按下”，因此先把 Claude 切到前台、把该行滚动到可见，用命中测试确认落点属于这一行后再真实点击（点在行左侧，点后鼠标指针放回原位）。
2. 打开后核对窗口顶部的会话标题与目标一致；输入框有草稿、出现多个输入框或正在运行（有「停止」按钮）时停止，不输入任何内容。
3. 把 Claude 切到前台、聚焦唯一输入框并粘贴（之后恢复原剪贴板），读回输入框与待发文字一致且会话未切换后才按回车，再切回原来的应用。
4. 只有该会话自己的 transcript 出现这条用户消息才算送达；否则标记为结果未确认，不重发。

2026-10-26 经用户授权，在专用会话「DragonTAC AX 测试」实测：Claude 原本在后台（前台为 Chrome），打开会话、核对、粘贴、发送约 1.7 秒，transcript 确认收到，前台切回 Chrome，Claude 只回复 `DRAGONTAC_AX_OK_20261026`。实测发现两点并已修正：Claude 在后台时侧栏不响应合成“按下”；命令行进程需运行事件循环才能读到最新的前台应用。

辅助功能读写由 `backend/models/desktop-agents/claude-ax.swift` 完成，首次使用时用 Xcode 命令行工具编译到系统临时目录；判断逻辑都在 `claude-desktop.js`，以模拟窗口测试。运行平台服务的程序需要在「系统设置 → 隐私与安全性 → 辅助功能」中授权（PM2 运行时为其使用的 node）；未授权、Claude 未运行或缺少命令行工具时，界面显示具体原因并保持只读。发送时会抢占前台、锁屏时无法发送；界面文字随 Claude 版本变化时会明确失败而不会误发。仅支持空闲时发送，运行中可排队，不支持引导。

### 网页会话视图

- 原会话使用首页「我的对话」同一个输入框；只读或投递结果未确认时输入框禁用并在占位文字中说明原因。平台模型、Skill、工作目录芯片等平台专属控件在这里隐藏。右侧工作区显示 Agent 会话的状态、发送能力、消息数和最近活动。
- 用户消息还原为客户端里实际看到的文字：Codex 的问答回执只显示回答，附件清单只保留“## My request”后的正文并以「[图片 #n]」占位；Claude 的频道唤醒、协调会话转发只显示消息正文，系统提醒、任务通知、本地命令输出不显示。
- 运行状态来自本地记录：Codex 看 `task_started` / `task_complete`，Claude 看最后一条消息是否 `end_turn`，Antigravity 看桌面的停止按钮；超过 20 分钟没有新事件不再视为运行中。运行中时时间线底部显示「正在处理 · 用时」。
- 轮询只增量更新：已显示的消息原地保留，只追加新消息或改写仍在生成的最后一条；同一轮连续的 Agent 段落合成一组，只显示一个头像。
- Antigravity 的长回复（“Worked for …”之后的正文）与短回复都会读取，并把渲染后的标题、列表、表格、代码还原为 Markdown；折叠的工作过程不读取。
- Agent 运行中可选择「排队」或「引导」（选择会记住）。排队消息保存在服务端，本轮结束后按顺序逐条发送，关闭网页也会继续，可在发送前取消；服务重启后未发送的排队消息丢弃。投递失败或结果不确定时停在该条并显示原因，不自动重发。引导仅 Codex 支持，使用桌面 IPC 的 `thread-follower-steer-turn` 把消息并入正在运行的这一轮，要求原会话已在 Codex 桌面打开；本轮已结束时拒绝并提示直接发送。
- 原会话忙碌、客户端不可用或桌面已有未发草稿时不替换任务或草稿。请求编号用于防止重复提交；结果不确定时不自动重发，先核对原会话。

DragonTAC 的升级任务、外部 Agent HUD 和本功能各自保留真实能力状态。这个菜单不会把 HUD 布局工具变成会话派发工具，也不会更改现有升级任务的执行通道。

## 同一 DragonClaw 对话内讨论

管理员在「全局设置 → 桌面 Agent」启用本机连接和 Web 发送后，通过输入框旁唯一的 **DragonTAC** 开关选择讨论组。未发送的新对话仍可反选并保留草稿；已有对话开启后立即保存并锁定，首次提交的新讨论也会锁定，避免同一对话混用两种模式。若需普通模式请新建对话。「我的对话」中讨论组标题左侧显示三个节点相连的标识，刷新后仍保留。普通平台对话开启时保留历史；从原生桌面或频道会话切入时建立新的平台讨论。首次发送为参与成员新建原生桌面会话；后续消息沿用本讨论组创建的会话，不复用无关历史。选择开关本身不发送消息，也不会停止已提交的讨论，停止仍使用发送区的停止按钮。

桌面连接未启用、关闭网页发送、没有可发送的客户端或连接检查失败时，开关置灰，悬停/辅助阅读可查看原因。仅有可读取的历史不代表可参与讨论；Claude 还需开启模拟操作发送。允许部分成员可用时发起讨论，其余成员保留具体不可用状态。连接状态在页面打开、设置变更、返回前台和前台每 30 秒重新检查；发起新一轮前再次检查。恢复已有讨论时保留讨论模式，连接不可用会明确阻止新消息派发，不自动改用平台模型代答。

首页微信、WeLink 标签和桌面客户端图标旁显示连接状态点：绿色表示正常，红色表示未连接/停用，黄色表示正在重连、配置待更新、长轮询延迟、近期可恢复错误，或桌面客户端只能查看而不能发送。客户端检测耗时超过 3 秒也标黄；悬停或辅助阅读可查看具体状态，不将忙碌等同于连接故障。点击分类/客户端会打开按最近活动时间排序的最新可见对话，排除归档和已移除记录，不因置顶而打开旧会话；快速切换时丢弃过期响应。右侧菜单的两秒悬停延迟保留，省略号图标缩小，触屏和键盘仍可直接操作。

每家依次回答同一问题，后续成员可参考前面成员已完成的意见。回复标记来源，保存在同一条 DragonClaw 对话。重新打开历史会恢复讨论组；正在执行时可「查看讨论」，只恢复进度而不重复提交。上下文与成员意见有长度上限并经过脱敏。

自动新建 Codex、Claude 会话目前使用 macOS 原生界面，需对运行平台服务的程序授予辅助功能权限。Claude 还需要开启「模拟操作发送」。Antigravity 使用运行中的桌面应用本地 CDP。任何成员不可用时显示具体原因，其余成员继续；不会改发到最近业务会话，也不会使用 CLI 或平台模型代答。

停止会停止等待及后续派发；已交给桌面的任务可能继续运行，需在原客户端停止。结果未确认不自动重试。平台重启后将未完成讨论标为中断，不重放。请求去重、会话归属和活动请求互斥按账号与租户实施。

### Antigravity 输入就绪修复（2026-10-26）

实机发现 CDP `Input.insertText` 可让 Lexical 文档出现文字，但上层 `isInputEmpty` 仍为真，发送按钮保持禁用。提交器现在等待原生按钮启用；必要时通过一次追加空格再删除的真实键盘编辑同步状态，全程核对目标路径、焦点和原文。只有确认文本一致且按钮可用后点击一次，并等待该会话的用户消息回执。

尚未发送的同文草稿可继续提交，其他草稿仍拒绝覆盖。按钮长期不可用时返回明确的输入未就绪错误并保留草稿；点击后的回执不明仍不自动重发。原生 Electron 测试覆盖延迟启用、内部状态需键盘同步、失败后同文重试只提交一次、其他草稿保留及结果不明保护。实机已恢复原来卡住的“你是什么模型”并收到回复，另一次独立多行首发验证成功。

讨论组的实时结果、恢复的成员消息以及单家桌面时间线使用各自 logo；同一成员连续回复只显示首条头像，切换成员或出现用户消息后恢复头像。实时轮询更新保留已有成员 DOM；成员之间与连续段落采用紧凑间距。

程序接口与原生桌面对话需区分：Codex 官方 app-server/SDK 可以创建、恢复线程和启动回合；本项目已有会话续聊使用桌面 IPC，新建仍经原生路由与 AX 确认提交。OpenClaw 的 Codex 插件使用 app-server，Claude Code 可由 ACP/运行时接入；这不自动等同于控制当前原生桌面窗口里选中的会话。Antigravity 的现有连接器使用 Chromium CDP，没有使用 macOS AX。本次未更换执行通道。
