# 内网直连共享对话（lan-share）

桌面版 + 公司内网时，把共享对话做成「每台电脑各自运行、经主持节点中转」的点对点共享。外网、服务器（基座）部署不启用。

代码：`backend/models/lan-share.js`（协议与节点运行时）、`backend/routes/lan-share.js`（本机界面，需登录）、
`backend/routes/lan-peer.js`（节点之间的接口与落地页，不登录）、`frontend/js/home/shared-conversations.js`（共享面板「内网直连」一栏、消息中心加入入口、`?lanjoin=`）。

## 启用条件

- `TOOLS_DESKTOP_RUNTIME=1`（Electron 启动时设置）；`LAN_SHARE=0` 可强制关闭。
- 内网判断复用 `channels/welink-network.checkIntranet()`（能解析并连通 WeLink 内网服务）。
- 本机内网地址优先 10.x.x.x，其次 172.16–31 / 192.168；端口取本机服务端口（默认 3030）。
- 节点接口只接受内网 / 本机地址的请求。

## 链接与身份

- 链接：`http://<主持内网IP>:<端口>/lan-share/<shareId>?t=<令牌>`。shareId + 令牌唯一标识共享：IP 被别人的电脑复用时，那边查不到这对组合，直接拒绝。
- 落地页探测本机 127.0.0.1 上的桌面版端口（3030–3035），找到后跳到 `http://127.0.0.1:<端口>/?lanjoin=<链接>`；未登录时登录页保留该参数，登录后自动加入。消息中心也可以粘贴链接加入。
- 每台电脑一个持久节点号（`lan_node.peer_id`）；加入时为该共享生成节点密钥，之后请求带 `x-lan-peer` / `x-lan-key`，按成员表里的 SHA-256 摘要校验（成员表分发给全体，所以临时主持也能校验）。

## 数据流

- 每个节点的控制库里都有一份完整的共享对话（复用 `shared_conversations` / `members` / `messages` 中转表）。加入者本地建一份 `owner = lan:<发起者节点>` 的共享，本机界面、推拉、实时围观照旧。
- 成员 → 主持：`POST /append`（本机新消息）、`POST /stream`（本机正在生成的回答事件）。两者共用一条有序队列，保证「先消息、后结束事件」。
- 主持 → 成员：长连接 `GET /live`（NDJSON：hello / state / log / stream / moved / closed / removed）；收到 `log` 后 `GET /log?after=` 拉取。心跳每 10 秒一次，顺带拉取，长连接断开时作为 HTTP 轮询兜底。
- 消息全局键 `origin = <写入节点>:<该节点中转序号>`（`lan_share_log`），各节点按 origin 去重；换主持后从头对账也不重复。
- 远端作者记为 `lan:<节点>:<账号>`，成员条里的远端成员为 `lan:<节点>`，显示名来自成员表。

## 地址变化、接任与收回

- 主持 IP 变化：心跳时发现 `selfUrl()` 变了，按已知地址向所有成员 `POST /host-changed`（同 term、新地址），链接随之更新。成员 IP 变化：心跳带上新地址，主持更新后分发。
- 主持下线：成员连续 3 次心跳失败后按加入顺序选举——排在最前、在线的成员以 `term+1` 接任并通知所有人；排在前面的成员在线时等它接任。
- 原发起者回来：探测成员发现更高 term 的主持 → 先跟随、把消息对齐（拉取 + 全量交给主持）→ 以更高 term 收回主持；临时主持卸任时把收录的全部消息交给新主持对账。
- 冲突：term 大者为准，同 term 时加入顺序靠前者为准。
- 发起者停止共享 → 所有成员收回本地副本；移除成员 → 对方副本收回、令牌轮换（旧链接作废）；成员退出 → 通知主持；临时主持退出 → 交给下一位在线成员。

## 已知限制

- 附件、生成文件的路径只在原电脑有效：正文与过程事件会同步，文件本身暂不跨电脑复制。
- 节点之间是明文 HTTP（与本机服务一致），只在内网使用。
- 网络分区时可能出现临时双主持，恢复连通后按 term 规则收敛。

## 手工验证（多进程）

单进程测试见 `tests/lan-share.test.js`。多节点流程用多个独立进程模拟多台电脑（不同数据目录、不同端口，`LAN_SHARE=1 LAN_SHARE_ADDRESS=127.0.0.1 LAN_SHARE_HEARTBEAT_MS=1500`），
用不同端口重启发起者即可模拟 IP 变化。已验证：加入与历史同步、三方互发无重复、实时流转发与中途 catchup、
杀掉发起者后第二位成员 6 秒内接任且期间消息互通、发起者换地址回来后 3 秒内收回主持且三端消息一致、
旧主持链接重定向到当前主持、移除成员后令牌轮换且无法再加入、停止共享后成员副本收回。
