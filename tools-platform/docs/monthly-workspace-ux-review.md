# 月报工作区体验审查（2026-10-11）

本次审查针对当前原生月报编辑器及实际浏览器回归结果。目标是降低日常操作的选择成本，保留高级配置，并把错误变成可以定位、恢复的问题。

## 本轮已落实

| 问题 | 改动 | 实际行为 |
| --- | --- | --- |
| 顶部并列大量按钮，主操作不突出 | 保存突出，导出合并为菜单，模板、Logo、工程和页面设置归入更多 | 原操作保留；菜单支持键盘与 Escape 关闭 |
| 报告状态和检查更新重复占用入口 | 保留可点击的数据状态入口 | 点击状态检查更新，原检查按钮不再占位 |
| 资料库长期增长，历史负担不断累积 | 默认最近90天，支持自定义0–36500天及加载全部 | 按导入 / 存档时间查询；0代表全部；不按业务月份裁剪原始记录 |
| 资料库范围会误伤月报引用 | 左侧目录与月报引用索引分离 | 必要时补充历史引用索引；保存结果与月份规则保持 |
| 左侧信息密度高，空分类很多 | 收藏 / 最近使用改为选项卡；类型 / 分类、来源详情折叠；隐藏空分类 | 用户首先看到表名、工作表和常用操作；筛选可一键清除 |
| 日志不够定位问题 | 底部加载日志 | 显示请求路径、HTTP状态、请求ID、耗时、各来源数量；不记录授权头或数据行 |
| 成功日志持续干扰 | 成功后4秒隐藏，失败保留 | 可以复制、重试、关闭；更多菜单可重新查看本次日志 |
| 编辑控件影响阅读 | 预览 / 继续编辑切换 | 预览隐藏正文控件、禁用文字编辑，保留阅读和跳转 |
| 目录失败后继续重试会延长卡住时间 | 首次目录失败时不自动补查全历史 | 释放编辑器并保留错误，由用户重试 |

加载范围会写入当前月报的资料库偏好，也记住本浏览器的最近选择。每份月报保存的偏好优先于浏览器偏好。日期范围只控制目录，单个工作表预览 / 引用仍按需读取；不会删除历史数据。

## 下一步优化优先级

### P1：编辑与配置的统一交互

- 元信息布局、快捷跳转布局和页面配置仍有独立入口；应逐步归入右侧的页面 / 组件配置，让正文只保留选中反馈。
- 组件工具栏虽然紧凑，但多个符号的辨识成本高。建议固定“移动、配置、更多”的结构，将映射、数字格式、复制、删除放入有名称的菜单，并保留现有快捷方式。
- 配置字段应有明确的分组、单位、默认值和校验位置；避免把错误仅放在顶部状态条。跨月来源错误应直接定位具体来源或字段。
- 保存状态建议统一为“未修改 / 有未保存更改 / 正在保存 / 已保存 / 保存失败”，配合最后保存时间与离开页面提示。

验收：不看说明即可完成找表、拖入、配置、保存；配置失败时能立即知道在哪个字段修复。

### P1：历史、模板和更新的可见性

- 报告名下拉同时承担定位和历史载入，后续宜提供独立的报告列表：月份、模板、保存时间与状态。
- 模板需要清晰的名称、版本和来源标识。新建月报可以收敛成“模板 → 报告月份 → 匹配结果”。
- 更新预览需要进一步展示记录数与关键值的差异，而不只显示来源版本变化；缺失字段应有修复入口。
- 历史结果展示应持续显示“保存结果 / 来源版本 / 当前有更新”等语义，避免用户把成功显示理解成最新数据。

验收：用户能回答“这份报告何时保存、用哪个模板、每个组件的数据来自哪次导入”。

### P2：规模与性能

- 当前按天限制服务器目录、按需读取工作表、分批显示条目。规模继续增长时，需要游标分页、服务器搜索与摘要索引，避免“加载全部”一次返回所有元数据。
- 当前日志中的服务端阶段耗时在响应后展示；慢请求期间只有请求阶段与累计等待时间。若以后需要实时看到服务器进度，应引入独立任务状态接口，而不是把数据库明细输出到日志。
- 透视和图表计算仍使用现有前端算法。大表需单独确定阈值与基准，再决定 Web Worker 或服务端聚合；不应只靠隐藏控件改善视觉。
- 需要真实数据规模的性能基线，以及 Windows EXE、不同缩放比例的持续回归。

验收：常用范围首次打开时间可测量；单源失败不阻塞编辑；目录总量增加不影响常用范围的操作响应。

### P2：视觉与可访问性

- 统一间距、输入高度、按钮层级、状态颜色与字体规格，减少小尺寸密集按钮。
- 中英文文案应表达业务意义，例如“对应月份最新”，避免实现名称进入主流程。
- 窄屏优先保留正文，把左右面板收为抽屉；支持键盘选择字段、组件焦点和菜单导航。
- 阅读预览与导出应进一步进行像素级对照，尤其是等高布局、长表、字体和图片。

这些是后续产品化工作项，不代表本轮已经全部实现。当前没有引入新前端框架、第二套存储或重写历史业务数据。
