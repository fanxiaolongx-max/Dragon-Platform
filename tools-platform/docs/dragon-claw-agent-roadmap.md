## 二、方案 A：工具注册表 + 按需加载

### A1 统一工具注册表（新文件 `agent-tool-registry.js`）
每个工具统一登记成一条记录：

```
id:          'core·read_file' / 'netcare·query_table' / 'mcp:figma·get_design'
source:      core | skill:<id> | mcp:<server>
description: 一句话简介（目录用）+ 完整说明和参数（加载后才给模型）
kind:        read | write | destructive          → 直接接现有审批
access:      adminOnly / readOnlyOk
loadMode:    always | deferred
execute(ctx, args)
```

现有服务**不重写**，只包一层适配：`agent-tools-service` 的定义和执行器、NetCare、运营、WeLink 各自注册进来。

### A2 按需加载（各家模型都能用，不依赖某个供应商的特殊功能）
- 常驻：少量核心工具（读文件、搜索、编辑等）+ 一个元工具 `tool_search`。
- 其余工具只在系统提示里列"工具名 + 一句话简介"。
- 模型调用 `tool_search({ query })` 或 `tool_search({ select: [...] })`，拿到完整说明后，这些工具**在本会话内保持已加载**，下一步的工具列表里就带上它们。
- 已加载的工具只往列表末尾追加、不调整顺序，这样前面的部分保持不变，模型那边的提示缓存才能继续命中。

### A3 Skill 改成"目录 + 按需加载"
- 系统提示里放 Skill 目录（13 个，约 600 token），模型可以自己调用 `load_skill` 加载正文，不再只靠 `@名称` 和正则。
- Skill 的 front-matter 增加 `tools:` 字段；加载 Skill 时自动把对应工具标记为已加载，取代现在"检查系统提示里有没有某段文字"的判断方式。

### A4 合并 6 套循环（放在后期阶段）
保留工作区循环作为唯一引擎，其余 5 套逐个改成"预设"：一段系统提示 + 允许使用的工具集合。每改一个，就跑一遍它原有的测试。

### A5 MCP 客户端（最后做）
- 管理员配置 MCP 服务（本机进程或 HTTP 地址），工具登记为 `mcp:<服务名>·<工具名>`，默认延后加载，默认每次调用都要审批。
- 需要新增依赖 `@modelcontextprotocol/sdk`，到时再请你确认。

### A6 工具清单页
仿照截图：按来源分组，显示每个工具常驻还是延后加载、占多少 token、被调用了多少次。

- 上下文面板显示「已加载 N 个工具，另有 M 个按需加载」。

### 第 4 阶段落地记录（2026-10-29）
- 工作区循环每一步开始前检查上下文占用：取估算值和上一步模型返回值中较大的那个，到窗口 80% 时（环境变量 `TOOLS_AGENT_COMPACT_RATIO` 可调）把较早的步骤整理成摘要，摘要沿用 `/compact` 的提示词（`ai-context-compaction.summarize`）。
- 只在一步的开头切分：用户消息，或带工具调用的模型消息。工具调用和结果始终成对；最近约 25% 窗口的步骤保留原文；用户本轮原话写进摘要和压缩记录。
- 保留多少按余量算：触发线减去系统提示和工具说明这部分固定占用，取其中 40%（最多 25% 窗口）。能压的内容不到窗口 10%，或压完仍超过触发线的 85% 时，不做压缩、直接整轮裁剪，避免每一步都反复压缩、白白多调用模型。每轮最多压缩 3 次。
- 整轮裁剪的兜底线从「窗口 75% − 输出」改到「90% − 输出」，中间 10% 是压缩缓冲（上下文面板的「压缩预留」相应变化）。摘要失败时本轮不再重试，由整轮裁剪兜底。
- 本轮做过压缩时，会话转录保存为压缩后的版本，并标记 `compacted_through_rowid`，重启恢复也不会拼回原文；每轮的完整过程仍在轮次档案里，导出日志能看到。
- 界面：压缩时状态显示「上下文快满了，正在把较早内容整理成摘要…」，完成后回复里留一行说明（压缩了多少条、约多少 token → 多少）。

### 真实环境测试（2026-10-29，3030 线上，Aragon / deepseek-flash）
通过：用量与缓存命中（Gemini 实际返回 76%）、大结果存文件（186KB 日志 → 文件卡片，上下文只占 2.6k）、模型自行 `load_skill`、deepseek 思考过程、导出日志（无 API Key）。

测出并修复的问题：
- 模型把未加载的工具名当 Shell 命令执行（`run_command("list_databases")`）。修复：只读数据库工具改为常驻；直接调用某个延后工具时整组加载；工具名被当命令时直接提示，不弹审批。
- 一步里并行调用多个工具、单步很大时，压缩被「压完仍接近触发线就不压」挡住，直接报上下文超限。修复：改为「能省窗口 5% 以上就压」，每轮上限从 3 次提到 6 次。
- 推理模型写摘要时把 2048 的输出额度花在思考上，摘要被截断。修复：摘要先用 4096，截断或空白时用 8192 重试一次。
- 兜底截短会截掉最近一步刚读回来的结果，模型因此把没看到的 ERROR 当成不存在。修复：按时间从早到晚截短，最近一步最后才动。
- 摘要输入把整条记录 JSON 截断，并行调用的后几个结果看不到，摘要只能记成「状态未知」，模型压缩后反复重读。修复：工具结果逐个列出，并摘出含错误、失败、超时等关键词的行。同一任务从 70 次调用、6 次压缩降到 25 次调用、1 次压缩，答案正确。

未修（记录）：`read_database_table` 只分页返回、不给总行数，模型统计行数时会推算出不准确的「至少 N 条」。

### 第 5 阶段落地记录（2026-10-29）

  - 回答被截断时续写；空回复时提示模型继续
  - 自动压缩和整轮裁剪
  - 大结果存成文件
  - 步数用完时不带工具做总结

### 常用内置工具（2026-10-29，插在第 6 阶段 MCP 之前）
全部离线，只用项目已有的依赖（acorn、exceljs、jszip、sqlite3），没有新增依赖。

**引擎自带的 3 个工具**（`agent-loop.js`，所有场景都能用；频道跟进任务只给计算）
- `update_plan`：任务清单。
  - 界面在工具行上方显示清单和进度，每次更新都整份替换。
  - 不出工具行，也不计入回复末尾的工具摘要。
  - 自动压缩时，清单会写进摘要的任务说明里。
- `ask_user`：提问并给出 2–6 个选项。
  - 问题和选项写进回复正文，所以频道和历史记录里也能看到。
  - 本轮随即结束；界面显示选项按钮，点一下就作为下一条消息发出。
  - 历史里的旧问题、以及用户自己回复过的问题，按钮都不可再点。
- `calculate`：精确计算。
  - 用 acorn 解析表达式，只认白名单里的运算和函数，不执行任意代码。
  - 支持四则运算、百分比、增减幅、统计函数和日期函数。
  - `workdays_between` 与 Excel NETWORKDAYS 一致，首尾两天都算；休息日可设成「周五、周六」。

**文件工具服务里的 7 个工具**（`agent-toolkit.js` / `agent-memory-repository.js`）

这 7 个工具放进按需加载的 `toolkit` 组，只在选了工作目录的对话里可用（首页对话目前没有文件上传）。只读账号只能用其中的读取类工具。

| 工具 | 作用 |
|---|---|
| `read_document`（读） | 读 Excel / CSV 的带行号表格，可分页；读 Word 的段落和表格；读 PPT 每页的文字和备注 |
| `query_data`（读） | 把表格载入内存 SQLite，执行一条只读 SELECT，支持多个来源关联查询 |
| `diff_files`（读） | 比较两个文件或两段文字的差异 |
| `multi_edit`（写） | 同一文件的多处修改一次提交，任何一处失败都不改动文件 |
| `zip_files` / `unzip_file`（写） | 打包和解压，改动可撤销 |
| `memory`（写，`list` 算读） | 长期记忆，见下一条 |

- PDF、旧版 .doc/.xls 和 .msg 邮件暂不支持。
- `query_data` 的只读限制：语句检查之外，还用 SQLite 的 `LIMIT_ATTACHED=0` 禁止挂载磁盘上的数据库文件。
- 压缩包的安全限制：
  - 原始路径带 `../`、或者是绝对路径的压缩包，直接拒绝。
  - 打包时跳过密钥文件和 node_modules 这类依赖目录。
- `memory` 长期记忆：
  - 按账号存在租户库的 `agent_memories` 表，最多 100 条。
  - 写入前脱敏，并拒绝密码、Token 等凭据。
  - 每次对话把本人的记忆放进系统提示。只有管理员在首页对话里才有：工作区和不选目录的对话都算；频道对话不带。
  - 新增、修改、删除都弹审批卡，卡上显示内容。

**大结果文件的补充**

单行 JSON 结果存成文件时，说明里会写出各个数组有几项（比如「tables：451 项」），并明确要求回答数量或完整列表前必须先读文件。改之前，真实模型只看开头结尾就猜「147 张表」；改之后答对了「451 张」。

**测试**
- 新增 `tests/agent-toolkit.test.js`，`tests/agent-loop.test.js` 补了用例。
- 全量 1825 个测试中 1824 个通过。唯一的失败是 `hosted_adc_sessions` 缺少数据表说明，来自工作区里另一批并行的托管应用改动，与本次无关。

### 首页对话附件上传（2026-10-30）
**怎么用**
- 输入框下方新增回形针按钮，也可以把文件拖到输入框里，或直接粘贴文件。
- 一次最多 5 个文件，单个不超过 20MB。
- 支持的格式：Excel / CSV / Word / PPT、文本、代码和常见图片。图片目前只能下载查看，模型还看不到图片内容。

**存在哪、谁能读**
- 选好文件就立即上传（`POST /api/ai/uploads`），存到 `<数据目录>/agent-uploads/<租户>/<账号>/<时间>/`，保留 30 天。
- 只有本人能读：`/api/agent-files` 对别人返回 403，管理员也不例外。
- 文件名会去掉路径符号，不在白名单里的扩展名直接拒绝。

**消息里怎么带附件**

  - 管理员的数据库对话直接加上这组工具。
  - 没有其他工具的对话（如非管理员）走 `ai-files-agent.runTurn`。
  - 频道对话不带附件。
- 选了工作目录时，文件工具也能按完整路径读本人的附件。

**测试**

测出并修复的问题：
- **网页请求被 DragonTAC 截走**：消息里只要有网址，再带上「打开 / 读取」等词，就会提议升级给外部 Agent。改为网页端管理员在浏览器工具可用时由 Dragon Claw 自己处理；明确提到 DragonTAC 时才提议升级，频道对话不变。

- **超长 JSON 读不全**：结果文件里 44KB 的 JSON 在一行里，`read_file` 截断超长行，模型怎么读都读不全。现在存文件前，任何超长的 JSON 行都会展开成多行，并在说明里写出各数组的项数。
- **审批被拒后换个写法再试**：审批被拒或超时时，返回给模型的结果里会明确说明不要换个写法重试同样的操作，工作区和不选目录的对话都一样。`browser_evaluate` 的说明也写明了每次都要审批，以及应该先用哪些工具。
- **界面显示**：

## 三、方案 B：上下文计量与压缩

### B1 窗口大小不再靠猜
模型配置增加"上下文窗口"字段（ai-settings），并内置一张常见模型的默认值表。用户手填的优先。

### B2 计量用真实数字，分类跟截图对齐
- `ai-provider-client.js` 解析各家返回的缓存命中数据：Anthropic 的 `cache_read_input_tokens`、OpenAI 的 `cached_tokens`、Gemini 的 `cachedContentTokenCount`。
- 分类改为：系统提示 / Skill / 工具（已加载）/ 工具（延后，不计入）/ 对话消息 / 工具结果 / 压缩预留 / 空闲，另外显示缓存命中率。
- 估算只用来做分项比例，总数以模型返回的数字为准（现在已经是这样，保留）。

### B3 大的工具结果存成文件，不再中间截断
- 结果超过约 8KB 时，完整内容存到 `backend/data/agent-artifacts/<租户>/<账号>/…`，上下文里只留开头、结尾和文件路径，并提示模型"需要时用 read_file 按行读取"。
- `read_file` 和昨天做的 `/api/agent-files` 只对**本人**放行这个目录。不能放进 `outputs/`，因为里面可能有数据库查询结果。
- 对话里会显示成可以点开、下载的文件卡片，用的是昨天做的文件卡片。

### B4 自动压缩：先生成摘要，删整轮只是兜底
- 每一步开始前，如果占用超过阈值（默认 80%，可配置），就把较早的几轮交给现有的 `ai-context-compaction` 生成摘要并替换掉，保留最近 N 轮，以及所有还没配对完成的工具调用和结果。
- 摘要失败时才退回现在的"整轮删除"。界面会提示"已自动压缩，较早内容已整理为摘要"。
- 预留一块压缩缓冲（默认为窗口的 10%），保证压缩本身有空间完成。

### B5 提示缓存友好（可选）
按"系统提示 → 工具 → 摘要 → 消息"的固定顺序拼装；Anthropic 模型加 `cache_control` 断点。
