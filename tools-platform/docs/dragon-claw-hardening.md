# Dragon Claw 分阶段修复与验证

本记录对应 2026-10-15 的工作区复核。账号能力保持：admin 可读写，普通用户只读；本地普通用户仍可选目录、发送工作区聊天。

## 当前产品决策：开放型 Agent

按用户后续确认，管理员选择“完全访问”表示授权 Agent 在当前任务范围内自主执行文件操作和 Shell；目录外访问、主目录或敏感路径的静态风险标记不再触发逐项审批。所选目录是 Shell 的默认位置，不是系统隔离边界，实际能力取决于服务进程的系统账号权限。

“请求批准”和“帮我批准”维持原有审批行为；普通用户始终只读。凭据脱敏、用户/租户会话隔离、操作记录、撤销冲突和 PR 既有改动保护继续保留。暂不推进强制 Shell 沙箱。

本次验证：6 个相关测试文件共 59 项通过，含真实子进程跨目录读写临时文件、不产生审批事件、继续下一步模型调用，以及普通用户不可借 full 模式写入的回归。后端 doctor、JS 语法及 diff 检查通过；没有重启 PM2 或重新打包。

## 第一批：撤销、归属与内容保护（已完成）

- 已有大文件取不到原始快照时标为不可撤销，避免误判为新增文件并删除。
- 修复新建后重命名、多次重命名、重命名后编辑/删除的撤销；原路径出现后续文件时默认拒绝覆盖。
- 快照整批替换使用独立 SQLite 事务，失败保留上一份记录。
- 会话在执行工具前校验并原子保留归属；聊天列表、读取、追加、归档、历史问题建议按租户及用户隔离；普通用户不能批准旧管理员写请求。
- 无归属历史保留原数据，不允许通过已知 ID 自动认领。需要迁移时应另做明确的归属迁移工具。
- 文件、搜索、Diff、工具结果、聊天及供应商消息增加凭据过滤；保护已配置的 AI Key、常见凭据字段/格式，保留供应商不透明思考签名。
- 凭据文件/别名不可由文件工具读取或编辑；数据库不可当文本覆盖。含可识别凭据的原文快照不落明文，重启后此类文件不可撤销；进程内原始快照仍可用于撤销。
- Git 只读检查禁用外部 Diff、textconv、fsmonitor；PR 使用字面路径，只提交会话文件，并在混入用户同文件既有改动时拒绝自动提交。

验证：后端 `npm run doctor` 通过；13 个相关测试文件共 78 项通过，包含租户隔离、备份边界和真实 HTTP 聊天归属检查。全部测试使用临时数据目录和随机端口。

限制：凭据过滤不是操作系统沙箱，不能识别任意编码或无标签的未知秘密；任意 Shell 仍可能越过目录和数据库边界。不能将本批视为所有凭据均无法泄漏的保证。

## 第二批：模型工具协议（已完成源码修复）

OpenAI 兼容接口现在从 `tool_calls[].extra_content.google.thought_signature` 读取签名，保留仅带签名的流式分片，经 SQLite 恢复后仍原样回传；明确为 Gemini 的旧转录使用官方兼容占位签名，普通模型请求不添加该字段。原生接口既有的签名支持继续保留。

依据：[Google 思考签名协议](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures)。新增流式/非流式、并行调用、重启恢复测试；供应商与运行管理器 26 项通过。

只读核对显示 PM2 `tools-platform` 的启动早于这次修改，尚未加载新源码。没有重启生产进程；模拟测试不代表当前在线网关已实测通过。

## 第三批：历史保留、大文件与上下文（已完成第一轮修复）

- 修正文件分页与外层 24K 输出限制不一致造成续读游标丢失；超长单行只保留有限前缀，流式扫描不积累整行。
- 移除聊天正文 20K、工具事件 400 条/400KB 的二次静默裁剪；Shell 保留工具已返回的输出（工具本身的超时、输出上限仍生效）。
- 新增租户库逐轮档案 `agent_session_turns`，每个工具步骤后检查点保存；完整档案不受模型转录 80 条限制影响。仅本人可通过 `GET /api/agent-workspace/transcripts/:agentSessionId?root=...&limit=...&offset=...` 分页读取。
- 已捕获的停止/失败轮次也恢复到后续模型上下文，未执行的并行调用补齐失败响应。
- 每次模型请求前按预算裁剪整轮旧上下文，必要时缩短工具结果副本；保留工具调用参数、签名与调用/响应配对，不改完整档案。无法容纳当前消息时明确报错，避免无界请求。

验证：相关 13 个测试文件共 86 项通过，后端 doctor 通过。覆盖 Unicode 多页连续读取、4MB 单行、长事件 JSON、失败后的重启恢复、完整档案归属及分页。

强制杀进程后的检查点与 `/session` 页面衔接已在下面的本轮复核中完成。仍需后续增强：模型对较早完整工具档案的按需检索。上下文预算采用保守估算，并非每个网关实际分词器的精确窗口。

## 第四批：工作区数据库工具（已完成首版）

新增 `list_databases`、`database_schema`、`read_database_table`，管理员与只读用户均可调用。支持当前租户的平台 SQLite 与工作目录中的本地 SQLite；默认/命名租户通过租户目录解析，禁止用所选目录里的运行库路径绕过隔离。

使用 SQLite OPEN_READONLY、query_only、trusted_schema 保护；仅结构化表/列/筛选参数，不接受任意 SQL，排除账号、AI/Agent 会话、凭据表、视图、虚拟表及敏感列。key/value 型凭据即使只请求 value 列也会脱敏；结果按行续读，长单元格及 BLOB 有明确省略提示。中英文工具卡片已补齐。

边界：首版支持表读取与简单筛选，不提供任意 SQL、联表、全库转储、数据库写入或远程数据库连接。平台检索仍按需通过工具进入，不自动把整库送给模型。

验证覆盖双租户切换、本地路径越界、运行库绕过、SQL 注入、视图别名、隐藏 key 列的凭据、宽表分页、普通用户工具权限。前端 JS 语法检查通过。

## 本轮修复与全面复核

### 修复

- 恢复历史对话时等待目录和智能体会话恢复完成，期间禁用输入与发送；原目录不存在时清空旧目录，避免用目录 B 执行对话 A 的任务。恢复普通聊天同样清理无关工作区，新对话会使旧恢复请求失效。
- 每轮档案保存恢复所需的前文、聊天关联和权限模式。重启后从最新逐步检查点恢复模型上下文，并把工具步骤及 Shell 输出接回原聊天；第一次尚未完成的聊天也能进入 `/session` 列表。
- 每个运行使用稳定的消息 ID 更新同一对问答，检查点、正常结束和多次读取历史不会重复追加；最终回答、审批事件及用量不会被后续档案同步覆盖。
- 已有工具结果原样接续；缺少结果的调用明确标为“操作状态未知”，提示先检查实际结果，不宣称未执行，也不会在恢复时自动重放工具。
- 切换目录或同目录的另一个会话后，忽略旧轮次的更改事件、完成结果、Diff 和刷新响应；撤销冲突确认绑定原目录与会话，避免确认期间切换目录后撤销了新目录的同名文件。
- 新增字段通过可重复迁移兼容已有数据库；继续按租户和用户校验归属。管理员 full 模式、普通用户只读和现有审批决策均保持原行为。
